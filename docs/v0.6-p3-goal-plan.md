# v0.6 P3 Implementation Plan：流式卡片回复与多 Workspace

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务推进。每个任务完成后先跑对应测试，再进入下一任务。

**Goal:** 在不破坏现有 text-only 路径的前提下，把 Feishu Agent Remote 扩展为支持 opt-in 进度卡片、runtime 增量进度，以及多个飞书 workspace / bot app 的本地远程控制服务。

**Architecture:** 先切出三个稳定 seam：`ReplyGateway` 负责消息/卡片传输，`ProgressReporter` 负责 run lifecycle 到 UI 的转换，`WorkspaceManager` 负责 workspace-scoped config/state/router/gateway。P3 分阶段落地：先 text-only progress interface，再 card fallback，再 runtime streaming，最后 workspace-scoped state 与多 consumer。

**Tech Stack:** Python asyncio、SQLite、`lark-cli`、Codex JSONL、Claude `stream-json`、现有 `remote_control/*` 模块、`unittest` fake gateway/runner/consumer。

---


### 0.3 安全边界

- 继续 owner-only / authorized-only 控制，不因 workspace 扩展放宽权限。
- `/send` 继续 approval-gated；workspace 化后 approval 必须绑定 `workspace_id`。
- repo allowlist 继续是必需项；shared repo 只能显式配置。
- 不把 app secret、token、user credential 写入 docs、tests fixture 或默认 config。

## 1. 当前基线

### 1.1 关键路径

当前主路径是：

```text
main.py
  -> load_config()
  -> StateStore(~/.feishu-agent-remote/state.sqlite)
  -> LarkGateway(lark_cli_bin)
  -> RuntimeRegistry(CodexRunner / ClaudeRunner)
  -> RemoteRouter
  -> CommandHandlers
  -> RunManager
  -> StateStore runs/sessions/remote_agents
  -> LarkGateway.reply(message_id, text)
```

### 1.2 现有限制

- `remote_control/lark_gateway.py` 只有 `reply(message_id, text)` 和 `send_user_message(user_id, text)`。
- `remote_control/run_manager.py` 只在 run final 后返回 `RuntimeRunResult`，没有 lifecycle callback。
- `remote_control/codex_runner.py` 和 `remote_control/claude_runner.py` 当前偏 final-result parsing；streaming 事件没有统一模型。
- `remote_control/state.py` 中 `sessions` 仍以 `(chat_id, thread_key)` 作为主键，没有 `workspace_id`。
- `main.py` 只启动一套 config/router/gateway/state 和一个 event consumer。

单 workspace 时保持当前简洁输出，不强制用户理解 workspace 概念。

## 9. 迁移与回滚

### 9.1 数据迁移策略

- 只做 additive migration。
- 所有新列默认 `default`。
- 不删除旧列：`codex_session_id`、root-level config 字段继续兼容。
- `run_replies` 是新表，删除该表不影响 core run/session。

### 9.2 feature rollback

出现问题时按顺序关闭：

```yaml
features:
  runtime_streaming: false
  card_replies: false
  progress_replies: false
  multi_workspace: false
```

关闭后预期：

- runtime 回到 final-result parser。
- 飞书回复回到文本。
- 只启动 default workspace consumer。

### 9.3 code rollback

如果已发布但需要临时回滚：

```bash
git revert <p3-merge-commit>
.venv/bin/python -m remote_control.cli service restart
.venv/bin/python -m remote_control.cli service status
```

不要 `git reset --hard`，不要 force push。

## 11. 风险与缓解

| Risk | 影响 | 缓解 |
| --- | --- | --- |
| 飞书 card API 与 lark-cli 封装不稳定 | card 功能阻塞或运行时报错 | card 全部封装在 gateway；默认关闭；失败 fallback text。 |
| streaming parser 抢占 final parser 语义 | 最终回复错误或 session_id 丢失 | streaming event 只用于 UI 增量；最终状态以 `RuntimeRunResult` 为准。 |
| 多 workspace 状态迁移破坏旧 DB | 用户丢绑定或 `/status` 异常 | additive column + default workspace；不强改旧 primary key；先 fake DB migration 测试。 |
| 多 consumer 日志难排查 | 线上卡住时难定位 workspace | 所有日志带 workspace_id；`/doctor` 显示 workspace view。 |
| 权限串 workspace | 安全问题 | auth、repo allowlist、confirmations、dedupe、sessions 全部 workspace-scoped。 |
| card 更新过频导致限流 | 进度体验变差 | status change 立即，文本进度 5 秒 debounce，final 必发。 |

## 12. Done Criteria

P3 只有在以下全部满足时才算完成：

- `progress_replies=false` 时，现有文本路径行为不变。
- `card_replies=true` 时，卡片创建/更新成功；失败自动 fallback 文本。
- `runtime_streaming=true` 时，Codex/Claude 中间 assistant 事件可转为 progress；final result 不回归。
- `multi_workspace=true` 时，至少两个 fake workspace consumer 测试通过，真实 smoke 至少验证 default workspace 不回归。
- SQLite 旧 state 文件可打开，旧 binding/run/agent 可读。
- `/doctor`、`/new`、`/status`、`/runs`、`/cancel`、`/send`、`/approve` 在 default workspace 回归通过。
- 完整本地测试、`py_compile`、`git diff --check` 通过。
